# ÆGIS ecosystem context

This repo is (or references) part of the ÆGIS ecosystem, built and operated by a solo developer:

- **aegiscloud.org** — Flask/Gunicorn backend on Railway, PostgreSQL, Cloudflare CDN, Resend for email, Stripe for Pro subscriptions (memory-token based).
- **aegiscode** (binaries: `aegis` / `aegis-cli` / `aegiscode`, same file) — a terminal AI coding agent (Node.js 22, TypeScript, React/Ink UI) that works with Claude, DeepSeek, Groq, and Ollama. Supports **both** BYOK (`ANTHROPIC_API_KEY` in `~/.aegiscode/.env`) **and** logging in with an existing Claude Pro/Max subscription via `aegis login --claude-pro` (prompts for a token from `claude setup-token` — Anthropic's own sanctioned mechanism for third-party tools, not a scraped/reused credential). Ships free cross-session semantic memory (local embeddings + sql.js, auto-indexed, no manual tagging). **There is no MCP server for memory** — despite some product pages implying one, the actual bridge is a set of one-shot CLI flags built for exactly this kind of external-tool integration: `aegis --memory-search-json "<query>" <limit>`, `aegis --memory-add-json "<content>" [role]`, `aegis --memory-stats-json`, `--memory-upload-json`, `--memory-download-json`, `--memory-clear-json`. All exit immediately with one line of JSON — no handshake, no server process. Pro-tier ($2/mo) adds `/council <question>`, `/debate <topic> [--rounds N]`, `/research <question>`, and `/multi <task>` / `/multiyolo <task>` (multi-agent orchestration). These are aegis-cli's own slash commands, but aegis-cli also has a headless `aegis --print "..."` mode that routes slash commands through the *same* dispatcher as the interactive terminal, confirmed working for `/council`, `/cloud status`, and others — so they can be invoked directly over Bash, not just composed for pasting. One caveat: `/multi`'s normal confirmation prompt has no UI to render in `--print` mode, so it silently runs unattended there (same effective behavior as `/multiyolo`) — worth flagging to the user before running it headlessly. Config persists to `~/.aegiscode/config.json` via `/model add|remove|list`.
- **ÆGIS Extractor** — a browser extension (Firefox + Chrome) that extracts conversations from 22+ AI platforms with local history and cloud sync.
- **rex.py** — a PyQt6 local security audit tool with ClamAV integration.

When working in this ecosystem:

1. **Never suggest or write API keys / secrets into shell startup files** (`~/.bashrc`, `~/.profile`, `~/.bash_profile`, `~/.zshrc`, etc.). This has caused real production billing failures before: a stray shell-level `ANTHROPIC_API_KEY` (or similar) silently overrides the project's local `.env` file and routes requests through the wrong provider/account. Always use project-local `.env` files instead, and say so explicitly if the user asks to export a key globally.
2. Treat this rule as absolute for this ecosystem — flag it even if the user's own request would introduce the pattern, rather than complying silently.
3. If asked to debug billing, routing, or "wrong model" issues, check for shell-level env var overrides shadowing `.env` before looking anywhere else — this is a recurring root cause in this codebase.
4. For memory, use `/aegis-recall` and `/aegis-remember` from this plugin — they shell out to the `--memory-*-json` flags above directly, no MCP involved. For `/council`, `/aegis-council` runs `aegis --print` directly since it's confirmed safe unattended. For `/multi`, `/aegis-multi` defaults to *composing* the command for the user to paste in (so the normal confirmation applies) and only runs it directly via Bash if the user explicitly asks, with the skipped-confirmation caveat surfaced first.
