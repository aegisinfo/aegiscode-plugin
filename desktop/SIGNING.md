# Code signing — AEGIS Desktop (Phase D3)

The public plugin repo now ships a **Windows `.exe`**, so Authenticode signing
is required for a trustworthy release. The chosen path is the
[SignPath Foundation](https://foundation.signpath.io) grant, which provides
free code-signing for open-source projects.

## Status

- **Not yet applied.** SignPath Foundation approval is an external process
  (OSS license check, repo-public verification, signing-policy review) that
  cannot be completed from the repo itself.
- The repo is MIT + public + zero-obfuscation, which satisfies the stated
  eligibility requirements — `desktop/` ships transport + UI only (CI-enforced
  by the thin-shell guard).

## What changes once the grant lands

1. Create a SignPath signing policy + project for `org.aegisinfo.aegiscode`.
2. Upload the project's signing certificate to SignPath.
3. Add the SignPath GitHub Action step to `.github/workflows/release.yml`
   (windows job) with the secrets:
   - `SIGNPATH_API_TOKEN`
   - `SIGNPATH_ORG_ID`
   - `SIGNPATH_PROJECT_SLUG`
   - `SIGNPATH_POLICY_SLUG`
4. Only then flip `CSC_IDENTITY_AUTO_DISCOVERY=false` off for the mac job and
   add Apple Developer ID notarization secrets if/when a cert exists.

Until then, CI releases unsigned artifacts (draft GitHub Release) — they are
clearly labeled in the release body.

## How the repo is kept signing-ready

- `desktop/electron-builder.yml` pins `appId: org.aegisinfo.aegiscode`.
- The Windows NSIS target is built in `.github/workflows/release.yml` on every
  `v*` tag push; artifacts land on a draft GitHub Release.
- Icons are generated by `npm run icon` (`desktop/build/icon.png`, 1024x1024 —
  swap in final brand artwork before the first tagged release).
